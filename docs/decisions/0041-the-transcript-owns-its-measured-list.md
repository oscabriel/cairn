# The transcript owns its measured list

`@foldkit/ui`'s virtual list estimates the height of rows it has never drawn and throws away measured heights on a width change, which is why scrolling up into unseen history jumps by up to 328 px and a width change loses the reader's place (stage 2.2; `docs/phase-2/notes/surfaces.md`). Neither can be fixed from outside the library. The transcript replaces it with a small list Cairn owns: exact, frozen row heights, off-screen history detached rather than estimated, and a glyph reader anchor that restores the character being read after a width change (after MonoCode's measured history, 176 lines). It is the look wave's first package, confirmed at the end of the daily-driver day.

Decided by the user on 2026-10-27, from the phase 2 area notes.

Gate evidence (package L1, 2026-10-29): `judges/transcript-scroll.ts` passed with `KNOWN_FAILING` empty, run under the judge lock on the 2,100-row harness. `range`: the 40-tick gesture travelled 6,400 px up and 6,400 px back down with the scroll range moving 0 px, no `scrollTop` or row reversal (the old list: 328 px steps and 17 reversals). `reflow`: the bookmarked glyph ended 0, 0, 0.5 and 0 px from its place at 900, 1,440, 390 and 1,440 px, worst frame 0.5 px (the old list: 25.3 px, worst 156.3 px). The new `insert-above` (a turn inserted three rows above the first visible one; the list made 510 px of room) and `arrive` (a late checkpoint card in a settled answer above; 156 px) moved the first visible row 0 times in 92 frames each. Broken controls: `--broken estimate` fails `range` (304 px steps, 17 reversals), `--broken reflow` fails `reflow` (129.5 px at 390), `--broken anchor` fails `insert-above` and `arrive` (88 frames moved, up to 24.5 px).

New `insert-far` and `arrive-far` checks make the same changes 60 rows above, where the rows are parked and measured off-screen: 510 and 156 px of room, 0 moves in 92 frames (`--broken anchor` fails both). `--broken bookmark` keeps only the first visible row through a width change: the row holds, but the glyph ends 24.5 px off at 390, so `reflow` fails and the glyph bookmark is needed beyond the row anchor. Second review round (2026-10-29): folding `FollowEnd.ts` into `Place.ts` made any wheel or key input up stop following, even input a nested scroller took (the open work group, a tool's output) or input over a list too short to scroll; no scroll event followed, so following never came back and the next reply streamed out of view. Input now stops following only when it can move the list up: the list overflows and is not at its top, no element between the input's target and the list can still scroll that way (t3code's `isTimelineScrollTarget`, #5566), and the wheel is not a pinch. A new `nested-wheel` check puts a scrollable box in the last row and wheels up over it (the box went from 1,000 to 700 px) then streams again: the end stayed within 0 px for 2.5 s and the pill stayed hidden; `--broken wheel`, the unconditional stop, fails it (the end 1,027 px away, the pill shown). Gaps are now watched for size as rows are, so a parked row leaving the list moves nothing: a new `remove-far` check takes a parked turn out 60 rows above (450 px of room) with no frame moving the first visible row more than 1 px (`--broken anchor` fails it with 176 frames moved; with the gaps unwatched it fails with 23.5 px). Corrections round `scrollTop` to the nearest whole px, and the land checks count a move as more than 1 px, as `extend` does: each correction rounds to within half a px of the held place, so two can step the row by up to 1 px (0.7 px seen on `remove-far`). An off-screen measurement dropped under a gesture now leaves the row's height stale, so the row is measured again once the gesture settles. A row that changed more than a buffer below the drawn window is not measured again until the reader nears it: the live reply, parked while the reader is about 6,000 px up, was drawn off-screen 88 times in 5 s and now once.

Measured cost, a gesture right after a width change: rows above the reader are laid out at their old-width height until measured again, nearest first, 12 a frame, and a stale row drawn on screen is corrected as it is. A new `range-after-reflow` check loads at 1,440 px, goes 1,600 px into history, narrows to 390 and 400 ms later runs the range gesture up: 6,400 px travelled, 0 px range steps, no reversal. The same gesture started at once after the width change is reported, not checked: range steps of up to 216 px in the first frames and 3 `scrollTop` reversals, with 0 content reversals, so nothing visibly moves, but on WebKit those `scrollTop` writes can cancel a fling that starts within about 100 ms of a rotation. Holding stale rows off screen during the gesture would show blank space where the reader scrolls, so the window stays.

As built, history the list never drew is measured off-screen before it joins the scroll range: up to 20 buffers ahead while the reader follows the end, then only after a pause near the range's top, and never while the reader scrolls, so the range holds under a gesture. The cost is a wall: a fling up through long history stops at the top of the measured range (in the probe, a 20,000 px wheel gesture stopped after 17,595 px) and more appears only after a 150 ms pause, in batches of 1,600 to 1,900 px (12 rows each) until 20 buffers are measured again. On a phone fling that can read as the thread's start. Measuring under the gesture would have to move `scrollTop` while the reader scrolls, which WebKit answers by cancelling the fling, so the wall stays; a sign that more history is loading at the range's top is left to the look track.
