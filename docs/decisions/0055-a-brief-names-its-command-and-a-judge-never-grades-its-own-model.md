# A brief names its command, and a model judge never grades its own model unless the user says so

The review of 2026-11-09 (findings V-9 and O-5) found two overclaims about outside judges. ADR 0026 and the glossary say a brief carries "how its result will be judged", but both brief constructors wrote the constant "The parent accepts the result" with a `user` judge, the card showed it as "judged by you", and nothing read it after a child settled. And a goal's `model` judge that names no model ran on the goal thread's own model (ADR 0043, decision 2), reading a transcript that model wrote, flattened to one string in which its own text could forge a user's line or a tool's output.

Decided by the user on 2026-11-09, as the reviewer recommended:

1. **A spawn names its command.** `subagent_spawn` takes an optional `done_when`, a command as an argv list that exits 0 once the work is done. It is frozen into the brief as a command criterion, shown on the brief card before Go ("Done when"), and given to the child in its first input with the ask to run it. Without one the brief keeps "The parent accepts the result.", and the card says what that is: "No outside judge; the parent accepts the result" (a workflow node's brief: the workflow script accepts it). The card never says "judged by you" for a brief.
2. **Cairn runs the command when the child's run completes** (deferred on 2026-11-09, built on 2026-11-10 with the user's approval, after-review package B; see "How the command is run" below). Its verdict is the settlement's check, which the parent's note states before the wake, and the work panel shows it as the "Checked by an outside judge" step. The card says "Judged by: An outside judge: Cairn runs the command in the child's workspace when its run completes", or, for a brief whose mode asks before a command, that it has no outside judge in that mode.
3. **A model judge on the thread's own model is refused unless the user picked it.** A judge that names no model would run on the goal thread's own model and is refused, at `goal_criteria`, at `goal.setCriteria` and at the judge run, with words the card and the verdict note show ("... is this thread's own model, so a judge on it would grade its own work"). The thread's model may not propose itself as a judge, through any provider (one model id is one model, so a bridge thread's model reached through opencode-go is still its own); the user may name it, in criteria the user sets or a bound criterion, since the user then chose it. This narrows ADR 0043's decision 2 for goal judges only; a subagent or a workflow node that names no model still runs on its parent's.
4. **The model judge reads fenced turns.** Each message of the judged transcript is a `<turn>` whose `from` (user, assistant or tool) Cairn sets; role labels (plain or in Markdown) and the fences' own tags are stripped from every turn's text until none is left, and its angle brackets are escaped, so an assistant message cannot forge a user's confirmation, a tool's output or the transcript's end; the system prompt tells the judge that a tool turn is evidence and an assistant turn is the judged model's own claim.

How the command is run (built 2026-11-10; it was the list of what running `done_when` still needed):

- **The run.** The reporter's commit that settles a completed run of a child whose brief names a command creates a check task (`cairn.subagent-check`, `subagents/DoneWhenCheck.ts`) in the child's conversation, so the command runs with `env.exec` through the child's own arms in its folder (its worktree, or the parent's checkout for a shared child), and the reporter waits on it in a new `check` phase between settling and `report`. The task runs the command as a goal's command judge does, through the same code (`verdicts/CommandRun.ts`, which `JudgeRun` now calls): no shell, the exit code, the output's last 4,000 characters and `HEAD`. Its time is the brief's `timeoutSec` (600 s); a timeout is not met, with no exit code and a note that says it timed out. A run that was stopped or failed is not checked, and its check says so.
- **The mode.** The task reads the child's effective permissions as its gated `bash` would (`readPermissions`), and does not run the command where a command asks first (Supervised, Auto-accept edits or Auto, unless the thread allowed `bash`): the child could not have run it unasked, and Cairn asking the user for a check is not built. The check is then "not run", naming the mode.
- **Crashes.** The task commits a mark (a task memo) right before the command starts. A brain killed while the command runs leaves the mark; the next boot reruns the task, which finds the mark and does not run the command again, since a `done_when` command may not be safe to run twice: the check is "not run", saying the brain restarted. A kill before the mark runs the command once on the rerun. So a kill neither loses the verdict nor runs the command twice. The reporter waiting on the task is a kept wait (ADR 0046); the task itself is not, since its rerun after the mark only commits. The note and the wake land once under their request ids, as before. Judged by `DoneWhenCheck.test.ts` ("a brain that dies while the command runs"): the brain closes with the command running, the next boot over the same store records the check not run, the parent gets one note and its wake, and the command started once.
- **The protocol.** `SubagentSettlement` and `cairn.child` gain an optional `check`. On a settlement it is the verdict for that result: `met` or `notMet` with the argv, the expected and actual exit code, the tail, the sha and a note, or `notRun` with why; absent when the brief names no command, and on settlements written before this. On `cairn.child` it is the child's latest check for the work panel, `pending` from Go until a run completes and `running` while the command runs. Both are additive; no stored shape changed, so no migration.
- **The note and the wake.** The settlement's note ends with the verdict ("Done when `pnpm test` exits 0: met, checked by an outside judge (exit 0)", "... not met ... (exit 1)" with the output's end in a `<check_output>` block, or "... not checked; <why>"). The wake follows by ADR 0028's rules, after the check: a not-met check wakes the parent as any completion does. A reporter that fails in its `check` phase reports the result with its check not run, saying why.
- **The scripted brain.** The dev and judge brains' scripted harness takes `done_when` too and runs the command the same way, synchronously, so the conformance scenario `subagent_result_done_when_met` holds both harnesses to the same note, and `judges/work-panel.ts` reads the done child's checked step (its brief names `done_when: ["true"]`, 5 of 5 steps).
- **The work panel.** `SubagentSteps.childStepsOf` adds a fifth step, "Checked by an outside judge", for a child whose brief names a command: to do until the child said what it did, now while the command runs, done when met, failed ("Not met by an outside judge", with the exit code or the timeout) when not, stopped ("Not checked by an outside judge") when Cairn did not run it.

Consequences: the glossary's Brief, Workflow and Outside judge entries say what is true now. A goal criterion bound before this ADR with a model judge that names no model is refused by `goal_check`, in the refusal's words, until the user names a model for it.
