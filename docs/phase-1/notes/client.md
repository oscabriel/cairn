## Summary

1. The client is a Foldkit 0.169.0 app. t3code's views are React shells of 5k to 9k lines each (`Sidebar.tsx` 5108, `ChatComposer.tsx` 7415, `ChatView.tsx` 8994, `MessagesTimeline.tsx` 5772). The plain-logic files beside them are what ports: about 12k lines of pure TypeScript plus their sibling `.test.ts` files, which are the cheapest outside judge for the ports.
2. The parity plan's file names are stale. It names `deriveTurnFolds` and `summarizeToolGroup` in `MessagesTimeline.logic.ts` (commit `5307c233`). At `fe27e8e3` the logic is `deriveMessagesTimelineRows` (line 1353 of 2321), and `summarizeToolGroup` moved to `packages/client-runtime/src/work-log/presentation.ts:651`. Several "plain" files are entangled with t3-only features (T3 MCP tool presentation, Codex directives, worktree setup, subagents, html-render, mcp-app) and need a trim, not a copy.
3. Phase 1 writes views by hand. S2's generated views (`spikes/2-foldkit/gen/dom2foldkit.py`, 315 KB of `src/t3/pages.ts`) stay as a baseline tool only: capture t3code's DOM per state, read it to get exact class strings, write the Foldkit view by hand, and let `judges/parity.ts` prove it. The CSS is t3code's `apps/web/src/index.css` (2454 lines), already in `spikes/2-foldkit/src/styles.css`, so identical class strings give identical pixels.
4. Keep the plain textarea for Phase 1, behind a one-module editor seam. The S2 typing gate passed on it. Tiptap inside a `Mount` is feasible (Foldkit's charting example is the pattern: Mount creates the handle, a module registry holds it, Commands drive it, a `Stream.callback` queue returns events), but it brings about 4k lines of t3code editor logic (`composer-rich-text-doc.ts` 1544, `ComposerPromptEditorTiptap.tsx` 1953, plus mentions, undo grouping, code blocks) and re-runs the typing gate on a new input surface. The user said chips need not match.
5. Foldkit gaps that Phase 1 must route around: `h.OnPaste` carries no clipboard data and `OnPastePreventDefault` carries only `text/plain`, so image and file paste needs `streamFromEventFilterMapPreventDefault` on `document` or a Mount listener (v1 already has the latter in `~/Developer/projects/cairn-v1/apps/web/src/mounts.ts`). `@foldkit/markdown` is build-time only, so chat markdown needs a runtime remark pipeline (v1 has one under `apps/web/src/markdown/`).
6. `@foldkit/ui` 0.169.0 covers most primitives: `virtualList` (dynamic row heights, `followEnd`, `scrollToKey`, `informItemsChanged`), `combobox`, `menu`, `popover`, `dialog`, `tooltip`, `toast`, `select`, `fileDrop`, `dragAndDrop`, `textarea`, `anchor`, `hoverIntent`.
7. The nightly baseline contains t3code brand elements that must not be copied: the `T3Wordmark` plus "Code" in `components/sidebar/SidebarChrome.tsx:117-130`, the nightly starfield backdrop (`SidebarStageBackdrop.tsx`, `@utility sidebar-stage-backdrop` in `index.css:502`), the `APP_BASE_NAME = "T3 Code"` and stage label in `branding.ts`, the favicons, the `t3code:` storage prefixes, the `t3/<hex>` branch prefix, `refs/t3/checkpoints`, the `t3-context://` scheme, and the built-in theme id `t3-chat`.
8. What a pixel judge cannot see and Phase 1 must still judge separately: hover actions, menus and popovers, the footer folding by width, row reorder animation, scroll anchoring, streaming. Each needs a state capture or a behaviour script (see Judges).
9. The transcript derives from pi-durable's `ConversationView` (`entries: EntryRecord[]` plus `docs`), not from t3code turn items, so an adapter produces t3code-shaped timeline entries from pi messages (`timestamp` in ms is on user, assistant and tool-result messages) before the ported folding logic runs.
10. Recommended build order inside the client: tokens and primitives, the shell store and sidebar, the hero and composer, the transcript, diffs, then settings. Each ends at a screenshot gate.

## Risks and open questions

1. **Tiptap or textarea.** Recommendation: textarea in Phase 1 behind the editor seam. Reason: the S2 gate passed on it, it makes iOS keyboard and IME behaviour native, drafts and triggers already work on plain strings, and it avoids about 4k lines plus a second typing-gate run. Revisit after the user has used it for a day; if chips are wanted, prototype the Mount in a spike with `judges/typing.ts` as the gate.
2. **Foldkit under streaming load plus editing.** The 0.168 keystroke-loss bug is fixed in 0.169.0 but only measured with the spike's cheap transcript. Phase 1's real timeline is much heavier. Recommendation: make `judges/typing.ts` run against the real app with a real streaming thread and a 500-row history, in `pnpm check`-adjacent CI (kept judge), and keep the `?busy` control.
3. **Paste data.** `OnPaste` gives no files. Recommendation: Mount listener on the composer plus a guarded document listener for type-to-focus pastes; unit-test `shouldHandleComposerAttachmentPaste` and run a Playwright paste test (`DataTransfer` with a `File`) at 390 px.
4. **Virtualization behaviour.** `@foldkit/ui` `virtualList` is new relative to LegendList's `maintainScrollAtEnd` plus `maintainVisibleContentPosition`. Unknowns: end anchoring while rows grow (streaming), "anchoring-new-turn", scroll memory per thread, dynamic heights with expanding tool rows. Recommendation: a short timeline spike with a 2,000-row fixture and a streaming tail, measuring scroll jumps (frames where `scrollTop` changes without user input), before committing; fallback is `content-visibility:auto` on keyed rows plus history paging (v1's approach).
5. **Transcript data adapter.** The ported folding logic expects t3code entries with run ids, attempt ids, tool lifecycle status and durations; pi-durable offers messages and `timestamp`. Decide the adapter's run and "Worked for" rules up front: turn = user message to last assistant message; elapsed = last assistant `timestamp + duration` minus the user `timestamp`; interrupted flag from an abort stop reason. Recommendation: write the adapter first, with tests on recorded pi transcripts (Phase 1 harness area), before any row views.
6. **Pixel judging of non-matching content.** Transcript text differs between apps. Recommendation: fixture importer (t3code thread projection to pi entries) plus structural comparison; accept that hover and animation rows are judged by behaviour scripts and by the reviewer model with explicit "not visible" listing.
7. **Reviewer model.** `parity-review.sh` uses `opencode-go/gpt-6-luna` because Codex login is revoked. Recommendation: keep it, add the new checklist rows, and have it also see the diff images.
8. **Brand removal changes the baseline.** The nightly shows the starfield and "T3 Code". Recommendation: the harness masks the header band (sidebar top 0 to 80 px at 1440 and the equivalent at 390) in both apps and lists "brand header" as an accepted difference; everything else must read "same as t3code".
9. **HEIC and LGPL.** `heic-to` is LGPL-3.0. Recommendation: ask the user; default is to skip HEIC conversion and let the server reject HEIC with a clear message, since iPhone screenshots are PNG and iPhone camera photos paste as JPEG in Safari.
10. **Drafts across devices.** t3code keeps them local. The user works from MacBook and phone. Recommendation: localStorage now (zero latency, no sync risk to typing), and a later optional `draft.save` command into the shell state if the user asks. Large pasted images stay as attachment ids, not data URLs, because uploads are eager and signed.
11. **Drag and reorder, snooze, pin.** The data model supports them (`pinOrderKey`, `activeOrderKey`, `snoozedUntil`), the interactions are large (dnd-kit plus sweep gestures). Recommendation: Phase 1 ships settle, unsettle, pin (menu and shortcut), snooze presets, rename, archive, mark unread, search and shelves; reorder by drag and the sweep gesture are deferred unless the user wants them. Say so in the plan so the sidebar row of the parity checklist stays honest.
12. **Server-owned inbox fields.** The client assumes these shell fields (from `OrchestrationV2ThreadShell`, `orchestrationV2.ts:1806-1879`): `status`, `pendingRuntimeRequest`, `latestUserMessageAt`, `lastVisitedAt`, `settledOverride`, `settledAt`, `snoozedUntil`, `pinnedAt`, `pinOrderKey`, `activeOrderKey`, `branch`, `worktreePath`, `lastErrorClass`. Confirm with the server notes that these exist in Cairn's shell stream, and that unseen-completion uses server `lastVisitedAt` (so the phone and the MacBook agree).
13. **Model picker content.** t3code groups by provider instance with favourites and per-provider traits. Cairn's models come from pi's `ModelRuntime`; roles (`@worker`) arrive in Phase 2. Recommendation: Phase 1 picker is provider-grouped with search and favourites stored in client settings; thinking is one select from the model's supported levels; runtime mode select has the four t3code values with full access default.
14. **Bundle and cold load (under 1 s on the phone).** Foldkit plus Effect is the baseline; shiki, `heic-to`, Tiptap, and diff libraries must be dynamic imports. Add a bundle budget check to the judges and measure the cold-load path with the existing S2 Vite build.
15. **Keyboard on touch.** Port `softwareKeyboard.ts` and the "Enter inserts newline while the keyboard is open" rule from the first composer commit, or the phone feels wrong immediately. Judge on WebKit at 390 px (the MacBook runs WebKit; the Beelink cannot, per S2 notes).

## Judges

Kept code lives under `judges/`. A step is done when its judge passes.

1. **Port tests.** Each ported logic file lands with its t3code sibling test (`Sidebar.logic.test.ts`, `Sidebar.snooze.test.ts`, `threadSort.test.ts`, `threadInbox.test.ts`, `shellReducer.test.ts`, `composerSubmission.test.ts`, `composerTypingGuard.test.ts`, `composerPromptHistory.test.ts`, `composerSlashCommandSearch.test.ts`, `composerAttachmentFiles.test.ts`, `composerFooterLayout.test.ts`, `textPaste.test.ts`, `MessagesTimeline.logic.test.ts` for kept rows, `presentation.test.ts`) running under vitest 5 in `pnpm check`. Cases that depend on deleted features are removed with a note in the header.
2. **Typing.** `judges/typing.ts` against the real app: 20 cps for 60 s with a streaming thread and a loaded sidebar, Chromium at 1440 and iPhone width, and WebKit iPhone width on the MacBook; also `--throttle 4` and `?busy=10`. Pass means zero dropped or reordered keys and IME composition `日本` intact. Add the menu case: typing `@`, `/`, `$` opens menus without losing characters.
3. **Parity screenshots.** `judges/parity.ts` extended with the states in "How Phase 1 writes views" at 1440x900 and 390x844, colour delta threshold 24, per-view budget 0% outside masked brand regions and 0.05% for ticking labels; plus a control that must fail (as S2's wrongly-open sidebar did at 71.3%). Output pairs and diffs under `~/Developer/agent-artifacts/cairn/v2/` for the user.
4. **Structural transcript judge.** For the imported conversation, compare per row kind: bounding box height and width, padding, font-size, line-height, colour, and presence of landmarks, between t3code and Cairn within 1 px and exact tokens; list rows absent on either side.
5. **Reviewer model.** `judges/parity-review.sh` with checklist rows from the parity plan's "Why it feels unpolished" table (sidebar, new thread, composer, transcript, look, shell) run over every pair; each row must read "same as t3code" except the declared brand diffs; "not visible" items are discharged by judge 6.
6. **Behaviour scripts (Playwright).** Footer folding: resize the composer through 900, 780, 700, 620, 520 px and assert which controls are visible, icon-only or in the overflow menu equals t3code's at the same widths (record t3code's states once as JSON). Triggers: type `/` at line start, `/tmp/x` (no menu), `@src` (path results after 120 ms), `$` (skills). Paste: a PNG `File` via `DataTransfer` creates one attachment chip and starts an upload; text over 32 KiB becomes `pasted-text.txt`; mod+shift+V keeps it inline. Drop: image and non-image files. Drafts: type, reload, text restored per thread and hero draft; switch threads, drafts stay separate. Sidebar: settle moves a row to Settled and the next row opens; undo within 5 s restores; snooze preset moves to Snoozed; search filters; context menu items match `ThreadActionMenuId`. Mobile: sidebar sheet opens and closes on navigation; Enter inserts a newline with the soft keyboard open (emulate with `visualViewport` resize on WebKit).
7. **Transcript scroll judge.** 2,000-row fixture plus a streaming tail: following the end holds within 1 px while streaming; scrolling up stops following and shows the scroll-to-end pill; switching threads restores each thread's position; no frame shifts `scrollTop` without input while a tool row expands. Memory and long-task budget recorded.
8. **Paste-to-model and load.** Phase 1 targets: a screenshot pasted on the phone is uploaded and in the model input within 2 s on the tailnet; cold load to an interactive thread list under 1 s on the phone. Measure with the harness (`performance.getEntriesByType("navigation")`, upload completion timestamps) and report numbers, not impressions.
9. **Brand judge.** A grep-style check in `pnpm check` (or a test) that fails on `T3 Code`, `t3code`, `T3Wordmark`, `t3-context`, `refs/t3` and `t3/` outside port headers.
10. **The user.** Final word on parity and on how far Cairn departs from t3code's look. The session's note from S2: the exact copy may not be what they want, so show both the t3code-matching state and any intentional departures side by side.
