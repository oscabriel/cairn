# Cairn phase 1 build plan

Written 2026-10-22 from the seven area notes in `docs/phase-1/notes/` (brain, bridge, server, client, effect, v1, edges), the kickoff's Phase 1 section and Targets (`~/Developer/agent-artifacts/cairn/v2/KICKOFF.md`), ADRs 0001 to 0015, `docs/coding-standards.md` and `GLOSSARY.md`. Pins: pi (`@earendil-works/*`) 1.4.0, Effect 4.0.5, Foldkit 0.169.0, Tailwind 4.3.3, TypeScript 7.0.2, Node 26.11, Agent SDK 0.3.305, t3code `fe27e8e3dc12dcbb108e9a28fd9b8cb65f34ae92` (ADR 0015).

The notes are the evidence; this plan is the decision. Where two notes disagree, section 2 says which one wins and why. An implementing agent given one work package from section 3 should read: this plan's sections 1 and 2, its package block, the note sections its block cites, and the installed source of every library it touches (CLAUDE.md, "Before using an API").

## Summary

Phase 1 builds the daily driver: a brain on the Beelink (pi-durable on one SQLite store, the user's models through a read-only `ModelRuntime`, Claude through a ported bridge, Executor tools under code mode, pi's skills), a Foldkit web client with t3code's inbox sidebar, new-thread hero, composer and transcript, signed attachments with document text, a PWA with Web Push, and Tailscale-identity sign-in at `code.gneiss.run`.

The work runs in five waves. Wave 1 starts with one sequential step that writes the frame and the protocol contract, then six packages build the skeleton in parallel. Waves 2 to 4 each have five to seven packages that touch disjoint files and depend only on earlier waves. Wave 5 runs in three short steps, because its parity fixes share tokens and primitives and its gate needs everything else finished. Shared wiring files (the composition roots) are edited only at the end of a wave (or step) by the integrator, from one-line hand-offs each package lists.

## 1. Architecture

### Repository layout

Standards S5 and S6 apply: `apps/*` are composition roots and never import each other; `packages/*` never import apps; a package exists because it has a second consumer.

```
packages/
  protocol/        @cairn/protocol: schemas, the one RPC group, JSON Schema export. Imports only effect.
  client-logic/    @cairn/client-logic: framework-free ports of t3code's client logic, plus the shell
                   reducer and the thread view applier. Imports effect, @cairn/protocol, @earendil-works/chord/delta.
  bridge/          @cairn/bridge: the Claude bridge as a pi-ai provider behind one Effect service.
                   Second consumers: the judges and the scripted harness.
apps/
  server/          the brain: Node composition root (main.ts, dev-main.ts, judge-main.ts)
  web/             the Foldkit client (Vite 8, Tailwind 4.3.3), plus public/ (sw.js, manifest, icons)
judges/            kept outside judges (typing, parity, durability, paste, load, push, gate, ...)
judges/fixtures/   judge-only Cairn extensions and fixture trees
judges/lib/        the Node protocol client, events-log reader and unit helpers the judges share
ops/cairn/         the systemd unit, install, deploy and Caddy route scripts
ops/relay/         the stdio relay unit `cairn-bridges`, its config and install (moved out of spikes/5, ADR 0014)

spikes/6-bridge-direct/   the timeboxed direct-registration attempt (ADR 0017's numbers)
```

### Modules

One line each. Paths are relative to the app or package `src/`. Every module is an Effect service with `static layer`, `layerNoDeps` and, where tests need it, `layerTest` (S37 to S41), unless it is marked pure.

Library boundaries (S42 as amended in 1.0, see D54). pi-durable is not one call site but the framework Cairn's tools and sections are written in, so its boundary is a folder plus a file-name convention rather than one service: runtime imports of `@earendil-works/pi-durable` are allowed only in `apps/server/src/brain/**`, in files named `*Extension.ts` anywhere under `apps/server/src`, and in `judges/fixtures/**`. Runtime imports of `@earendil-works/pi-ai` are allowed only in `brain/**`, `models/**`, `*Extension.ts` and `packages/bridge/**`; `import type` of pi-ai content types is allowed anywhere in the server. `@earendil-works/pi-coding-agent` is imported only in `models/PiModelSource.ts`, `models/PiConfig.ts` and `skills/**` (`loadSkills`, `formatSkillsForPrompt`, `loadProjectContextFiles`); the Agent SDK only in `packages/bridge/src/ClaudeSdk.ts`. An oxlint `no-restricted-imports` override per library enforces this. Everywhere else, modules see Cairn schemas and services.

### The protocol (ADR 0007, made concrete)

One RPC group, `CairnRpcs`, over one WebSocket at `GET /ws?protocol=1` (other values get HTTP 426 `{code: "protocol_incompatible", protocol: 1}`), `RpcSerialization.layerJson`, one `RpcServer` per socket built with `RpcServer.makeProtocolWithHttpEffectWebsocket` and run with `{disableTracing: true, disableFatalDefects: true}`, `perMessageDeflate: true`. Identity decided at the upgrade reaches handlers through `ViewerMiddleware` (upgrade headers are appended to every RPC request).

| RPC | Kind | Purpose |
| --- | --- | --- |
| `session.hello` | unary | protocol, build id, server time, defaults, VAPID public key |
| `shell.subscribe` | stream | shell stream: `snapshot`, `project.updated`, `project.removed`, `thread.updated`, `thread.removed`, `synchronized`; resumes from `afterSequence` (gap cap 1,000, snapshot fallback, pruned-floor and above-high-water cases) |
| `shell.dispatch` | unary | inbox and project commands, idempotent by `commandId` |
| `thread.launch` | unary | create a thread with a workspace strategy and first message, idempotent by `commandId` |
| `thread.send`, `thread.stop`, `thread.withdraw`, `thread.configure`, `thread.respond`, `thread.retryTask` | unary | turn input (idempotent by `requestId`), stop with or without clearing the queue, withdraw a queued input, model and thinking changes, answer an approval, retry a parked task |
| `thread.subscribe` | stream | thread stream: `snapshot {seq, view, entriesOffset, hasMoreHistory}` then `ops {seq, ops}`; a fresh snapshot on every subscribe; an in-stream `snapshot` is legal at any time |
| `thread.history`, `thread.entry` | unary | older pages via `conversation.entries()`; a full entry up to 256 KiB |
| `projects.browse`, `projects.ensureScratch`, `projects.searchEntries`, `git.branches` | unary | folder picker, the scratch project, `@` file search (`git ls-files` then `fd`), base branches for the context strip |
| `attachments.createUploadUrl`, `attachments.discard` | unary | signed one-shot upload URL |
| `diff.turn`, `diff.full` | unary | per-turn and whole-thread diffs from checkpoint refs |
| `models.list`, `providers.status` | unary | the model picker and provider credential status (OAuth logins join in Phase 2) |
| `usage.subscribe` | stream | plan windows and provider usage |
| `skills.list`, `skills.reload` | unary | `$` and `/` completion |
| `executor.status`, `executor.signIn` | unary | Executor link health and re-sign-in |
| `push.subscribe`, `push.unsubscribe`, `presence.report` | unary | Web Push |
| `settings.get`, `settings.update` | unary | server-owned settings |

HTTP routes on the same listener: `/` and hashed `/assets/*` (static, SPA fallback only for `Accept: text/html` and never for `/api`, `/ws`, `/_cairn`, `/oauth`), `GET /api/shell`, `POST /api/attachments/upload/:token`, `GET /api/attachments/:id/:variant`, `GET /api/threads/:threadId/entries/:entryId/images/:index` (tool-result images, signed short TTL), `POST /api/load-report` (beacon, written to the log), `GET /oauth/executor/callback`, `GET /_cairn/auth`, `GET /_cairn/health` (loopback only).

`ThreadShell` fields (optional ones are `Schema.OptionFromNullOr`, so `null` on the wire and `Option` in the server and the client, S22 and S23 as written): `id, projectId, title, provider, modelId, thinkingLevel, runtimeMode, branch, worktreePath, activity (idle | preparing | running | waiting | parked | failed), activeRunId, latestRunRequestedAt, latestRunStartedAt, latestRunCompletedAt, queueLength, lastError, lastErrorClass (usage_limit | provider_error | transport_error | unknown), usageLimitResetAt, waitingFor (claude_slot | none), pendingRuntimeRequest {id, kind, createdAt}, latestVisibleMessage {entryId, role, text, at}, latestUserMessageAt, createdAt, updatedAt, archivedAt, settledOverride, settledAt, unsettledAt, snoozedUntil, snoozedAt, pinnedAt, pinOrderKey, activeOrderKey, autoSettleDisabledAt, lastVisitedAt, parkedTaskIds`. Unseen completion is `latestRunCompletedAt > lastVisitedAt`, computed by the client from server fields, so every device agrees.

The thread stream's view is a projection (`ThreadWire`, ADR 0020): only `pi.agent`, `pi.live`, `pi.inbox`, `pi.usage` and `cairn.approvals` docs; `pi.provider` and `pi.system` hidden; `cairn.claude` diagnostics stripped from entries; base64 image data replaced by a reference; strings over 32 KiB truncated with t3code's marker and `truncated: true`; and, only if `judges/wire-budget.ts` fails on the projection alone in wave 4, a window of the last 10 user turns with `entriesOffset` and server-side op index rewriting, re-snapshotting whenever a rewrite cannot be proven.

Client connection rules: `RpcClient.layerProtocolSocket({retryPolicy: Schedule.recurs(0), pingInterval: "3 seconds", pingTimeout: "8 seconds"})` inside a Foldkit `ManagedResource`; Model-owned states `Connecting`, `Syncing` (until the first shell snapshot), `Live`, `Backoff {attempt}`; backoff 0, 100, 200, 400, 800, then 1,000 ms with 20 percent jitter; an immediate attempt on `online`, `pageshow` and `visibilitychange`; every reconnect resubscribes the shell with its in-memory cursor and takes a fresh thread snapshot. Mutations are never replayed by the transport: the `Outbox` (localStorage FIFO keyed by `requestId` or `commandId`) resends after reconnect and pi-durable or the receipt table dedupes.

### The harness seam

The seam is thread-keyed, because one store holds every thread (ADR 0016). It is t3code's `ProviderAdapterV2` reduced to what a durable in-process loop needs; its event vocabulary is not ported (the thread stream is pi-durable's own view).

```ts
class HarnessSeam extends Context.Service<HarnessSeam, {
  ensureThread(input: EnsureThread): Effect.Effect<ThreadHandle, HarnessError>          // receipt + createConversation + configure, one commit, idempotent
  configure(threadId: ThreadId, change: AgentChange): Effect.Effect<void, HarnessError>    // cwd only while idle
  submit(threadId: ThreadId, input: TurnInput): Effect.Effect<SubmissionRef, HarnessError> // idempotent by requestId; whenBusy steer | followUp | reject
  stop(threadId: ThreadId, options: StopOptions): Effect.Effect<void, HarnessError>        // clearQueue false: abortTask(run); true: conversation.abort
  withdraw(threadId: ThreadId, submissionId: SubmissionId): Effect.Effect<WithdrawResult, HarnessError>
  respond(threadId: ThreadId, approvalId: ApprovalId, decision: ApprovalDecision): Effect.Effect<void, HarnessError>
  watch(threadId: ThreadId): Stream.Stream<ThreadFrame, HarnessError>                       // snapshot then ops, already projected by ThreadWire
  history(threadId: ThreadId, query: HistoryQuery): Effect.Effect<HistoryPage, HarnessError>
  entry(threadId: ThreadId, entryId: EntryId): Effect.Effect<FullEntry, HarnessError>
  readonly events: Stream.Stream<HarnessEvent>                                              // all threads, committed only, from subscribeCommits
  inspect(): Effect.Effect<ReadonlyArray<LiveThreadState>, HarnessError>                    // boot reconcile
  retry(taskId: TaskId): Effect.Effect<void, HarnessError>
  readonly capabilities: HarnessCapabilities
}>()("cairn/server/brain/HarnessSeam") {}
```

`HarnessEvent` is a union of upserts keyed by pi-durable's stable integer ids: `ThreadEnsured`, `RunStarted {threadId, runId, at}`, `RunTerminal {threadId, runId, status: completed | interrupted | failed, failure?: {class, retryable, resetAt?}, at}` (the only completion signal; the projector, checkpoints and push key on it), `MessageCommitted {threadId, entryId, role, text, at}`, `QueueChanged {threadId, length}`, `RuntimeRequestUpdated {threadId, id, kind, status}`, `UsageUpdated`, `TaskParked {threadId, taskId}`, `CompactionStarted`, `CompactionEnded`.

Two implementations:

- `PiDurableHarness`: the real one, over `Brain`. `events` comes from `harness.subscribeCommits` (one subscription for every thread; the listener only enqueues). Stop keeps the queue by default (`abortTask` on the run task), which matches t3code's queued runs; the composer offers "clear queue" separately. The bridge's explicit abort is called from `Threads.stop` through `ShutdownHooks`-style `StopHooks` (wave 3), because a held Claude query outlives its generation signal.
- `ScriptedHarness`: an independent in-memory implementation that plays scripted transcripts (a hand-maintained `ConversationView` updated through chord's applier). It is the deterministic backend for UI tests, screenshots and the client in dev mode.

The replay conformance suite (`registerHarnessConformance(runner, name, makeHarness)`, in the shape of pi-durable's `registerEnvConformance`) runs one set of NDJSON scenarios against both. Transcript lines: `transcript_start {scenario, version}`, `input {step: message | steer | followUp | stop | stopClear | withdraw | respond | restart, text?, requestId?}`, `model {label, message}` (a pi-ai assistant message; the pi-durable side feeds it to pi-ai's faux provider, the scripted side emits the equivalent entries), `tool_result`, `crash` (reopen over the same store), `expect_event`, `expect_view {path, equals}`. The `expect_event` and `expect_view` lines are written by hand for every scenario from the seam's contract (what t3code and the kickoff require), not recorded, so the suite judges pi-durable rather than replaying it. Recorded goldens (normalized, ids and timestamps masked, from pi-durable plus faux with a fake `now` and `setTimer`) exist only as drift detectors: a golden diff fails with "behaviour changed, review it", never as the proof of correctness. Phase 1 scenarios: `simple`, `multi_turn`, `tool_call`, `queued_turn`, `message_steering`, `whenbusy_reject`, `stop_keeps_queue`, `stop_clears_queue`, `withdraw`, `idempotent_resubmit`, `ensure_thread_raced`, `image_content`, `provider_error_usage_limit`, `failed_run_keeps_queue`, `compaction`, `resume_after_restart`, `approval_answered`, `approval_across_restart`. The mutation check runs on both sides: a broken `ScriptedHarness` and a wrapper around `PiDurableHarness` that drops `RunTerminal`, reorders events, loses a queued input and skips the snapshot on `watch` must each fail at least five scenarios.

### How the bridge plugs in

- `@cairn/bridge` is a native pi-ai provider (`claude-bridge`), ported from pi-claude-bridge 0.9.3 (`874fa7c2`), dot314 and v1, not registered from upstream (ADR 0017, with numbers from `spikes/6-bridge-direct/`).
- Registration: `models/BridgeProvider.ts` provides the `Claude` service's `provider` to `PiModelSource`, which calls `ModelRuntime.registerNativeProvider`. `auth.apiKey.check` reads `ClaudeAccount` (the cached probe, no spawn); a child that reports any `apiKeySource` other than `none`, or any tool, fails the turn.
- cwd: a Cairn extension `bridge-cwd` (`brain/BridgeCwdExtension.ts`) with `hook(GenerationTask, {beforeRequest})` reads `AgentDoc.cwd`, `ProviderDoc.sessionId` and the thread receipt and calls `Claude.noteConversation(sessionId, {cwd, threadId})` before every attempt; the child runs in the realpath of the thread's real cwd. A cwd that differs from the stamp's means a fresh session. Side effect on the user's files: children write transcripts under `~/.claude/projects/<escaped realpath>/`, so Cairn's sessions appear in the user's interactive `claude --resume` list for that folder, and the user's own `claude` sweeps them by its `cleanupPeriodDays`. Moving `CLAUDE_CONFIG_DIR` is not an option because it would move the credentials too; this is recorded in ADR 0017's consequences and the wizard's open questions.
- Session id: the stamp on the final `AssistantMessage` (`diagnostics: [{type: "cairn.claude", ...}]`, ADR 0018), committed atomically with the reply, following entries into forks; `ThreadWire` strips it. The first session's id is set to pi's provider session id (a UUIDv7) so a kill during the very first reply still finds the transcript.
- Resume: SDK-native `resume` plus `resumeSessionAt` (plus `forkSession` after a real abort or child error). Cairn never rebuilds Claude Code's transcript (kickoff). When history diverged (a pi compaction, a provider switch mid-thread, a changed cwd or model, a swept or missing transcript), `ClaudeResume` opens a fresh Claude session whose first prompt is pi's current context (the compaction summary plus the kept tail, rendered as text with images carried), stamped as a new session; native resume continues from there. That costs one cache write per divergence, which is what a compaction costs anyway.
- Abort: one signal per conversation; only a `DOMException` `AbortError` is real; `Threads.stop` also calls `Claude.abortConversation(sessionId)`; shutdown calls `beginClosing()` before `harness.close()`.
- Concurrency: `ClaudeSlots` (a `Semaphore` of 4) counts generating children only; an `RcMap` caps live children at 12 with a 10 minute idle time to live. `Claude.offered` reports which threads wait for a permit; 3F's `ClaudeSignals` layer feeds it to the shell projector through the `ProjectorSignals` service, which sets `waitingFor: claude_slot`, shown as "waiting for a Claude slot".
- Settings: compaction for `claude-bridge/*` stays enabled for blocking and overflow recovery with `backgroundTokens: 0` and a small `reserveTokens` (16,384) so blocking compaction is rare (`settings.compaction.modelOverrides`); system-prompt changes after a session starts reach Claude as one `<system-reminder>` on the next user message; `assertSendablePrompt` refuses pi's preamble and documentation lines.
- Isolation: `tools: []`, `settingSources: []`, `strictMcpConfig: true`, `settings: {disableAllHooks, autoMemoryEnabled: false, includeGitInstructions: false, claudeMdExcludes, cleanupPeriodDays: 3650}`, `ANTHROPIC_*`, `CLAUDE_CODE_OAUTH_TOKEN`, Bedrock and Vertex flags and `CAIRN_*` stripped; `ENABLE_CLAUDEAI_MCP_SERVERS=0`, `DISABLE_AUTO_COMPACT=1`, `CLAUDE_CODE_FORK_SUBAGENT=0`, and `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` on turn children only (never in `process.env`, the probe needs it unset); MCP tool `timeout` 4 hours.
- pi-ai's own Anthropic OAuth is refused in four layers (credential store, `AuthContext` env, a replacement `anthropic` provider without `auth.oauth`, the picker), plus an oxlint `no-restricted-imports` rule on `@earendil-works/pi-ai/providers/anthropic` and `@earendil-works/pi-ai/providers/all` outside `models/AnthropicGuard.ts` (pi-ai's `exports` reach the OAuth login only as `anthropicProvider().auth.oauth.login(...)` and through `builtinProviders()`; `./oauth` is types only); the `sk-ant-usr` key in `auth.json` is hidden.
- Usage windows: probe plus `rate_limit_event`s, window mapping ported from t3code `fe27e8e3` `claudeUsageLimits.ts`; reported on `usage.subscribe`; a plan-window rejection's error text starts "Claude plan quota exceeded" so pi-ai does not retry it, `brain/RunFailure.ts` maps that run's `RunTerminal` to `lastErrorClass: usage_limit`, and `ClaudeSignals` supplies `usageLimitResetAt` from the window that rejected.

### Executor tools

- `ExecutorLink`: one long-lived pi-mcp `McpClient` with `StreamableHttpTransport({url, authProvider, openGetStream: false})` and one shared `adaptOAuthProvider` (concurrent refreshes share one in-flight refresh; Executor treats a reused rotated refresh token as theft). No `elicitation` capability, so Executor uses model elicitation mode.
- The grant: imported once from `~/.config/cairn/executor-grant.json` into `executor_grant` in `cairn.sqlite` in one transaction, then the file is renamed `executor-grant.json.imported` and deleted after the first successful refresh. A lock (`~/.local/state/cairn/executor.lock`, `flock`) ensures one holder. Only the production brain (`main.ts`) composes the real link; `dev-main.ts` and `judge-main.ts` compose `ExecutorLink.layerFake` (port of v1 `fake-executor.ts`). `needsSignIn` status and an `executor.signIn` flow through `/oauth/executor/callback` exist for a revoked grant.
- Five proxies (`executor/ExecutorExtension.ts`), `executor_skills`, `executor_search`, `executor_describe`, `executor_call`, `executor_execute`, all `callers: ["tools"]` under a code-mode namespace `executor`, so the model's tool list is fixed (coding tools plus `codemode`). `resume` is internal, never a tool (ADR 0003 amended).
- Scope per call, with no per-project setup: refuse the `executor` app, refuse GitHub calls that name a repo other than the project's (`RepoIdentity`), filter discovery results (port of v1 `callRefusal`, `gitHubRefusal`, `filterSearch`, `filterDescribe`, `filterSkills`, `executeRefusal`).
- Approvals (ADR 0013): every call and execute goes through `GatedCall`: commit a `cairn.approvals` record; in full access (the Phase 1 default and only product mode) it is approved at once; commit `started`; call; on `approval-required` commit the `apr_` id then `resume accept`; commit `done`. A rerun that finds `started` returns "Interrupted after it started, so it may have run. Not retried." At boot, `ExecutorSweep` declines every recorded `apr_` whose call never finished, then `retryTask()` for tasks whose approval is still pending. `input-required` forms are cancelled with a clear error in Phase 1. Permission modes other than full access, and approval cards in the UI, are Phase 2; `thread.respond` exists in Phase 1 and the durability judge uses it.
- Stdio servers stay behind the stdio relay unit `cairn-bridges` (ADR 0014); Cairn treats each Executor call as stateless. The unit and its config move from `spikes/5-stdio-bridges/` into `ops/relay/` (1E), keeping `KillMode=control-group` and the ports 3775 and 3776.

### Skills and context

- `PiConfig` reads `~/.pi/agent` strictly read-only: `SettingsManager.fromStorage` over a read-only storage (no `create`, which locks `settings.json`), `new DefaultPackageManager({...}).resolve(async () => "skip")` (never `DefaultResourceLoader`, never `PI_OFFLINE`), cached against the mtimes of `settings.json`, `~/.agents/skills`, `~/.pi/agent/skills` and package roots. The user's `+` and `!` skill filters are honoured.
- `SkillCatalog.forCwd(cwd)`: project `.agents/skills` up to the repo root first, then the resolved user skills; first name wins; dedupe by realpath; sorted by name; `disableModelInvocation` skills listed for completion but kept out of the prompt; project `.pi/` is never read. Refreshed at thread start and on `skills.reload`, never per model call.
- Sections (Cairn extensions, rendered synchronously from cached snapshots so they are byte-stable): `cairn` (one paragraph naming the arms path and `searchTools()`), `skills` (`formatSkillsForPrompt(visible, "read")`, about 30 KB today), `context` (`AGENTS.md` and `CLAUDE.md` from the agent dir and workspace, `APPEND_SYSTEM.md`, regular files only, 64,000 character cap).
- `$name` and `/skill:name` in the composer send `skillRefs`; the `SkillExpansionStage` (a `TurnContent` stage that runs before attachments) produces pi's exact `<skill name="..." location="...">` block so a thread continues in pi.

### Attachments

- `attachments.createUploadUrl({name, mimeType, sizeBytes})` returns `{attachmentId, uploadPath, expiresAt}` with HMAC-signed claims (`version, kind, attachmentId, name, mimeType, sizeBytes, expiresAt`), key `~/.config/cairn/upload-signing.key` (32 bytes, `wx`, 0600), TTL 10 minutes, time from `Clock`.
- `POST /api/attachments/upload/:token`: guard, signature and expiry, `Content-Length === sizeBytes`, stream to `.tmp/<id>.<uuid>.part` while hashing, rename, sniff the bytes (PNG, JPEG, GIF, WebP, `%PDF-`, DOCX zip, strict UTF-8 text; HEIC and video refused), prepare, answer `200` with the `AttachmentRef`.
- Preparation at upload, never at send: images through pi-durable's Photon worker (`createNodePhotonImages`) fitted to 1,568 px on the long edge, stored as binary; PDF text through `unpdf` (`isEvalSupported: false`, a copy of the buffer, page boundaries kept) and DOCX through `mammoth`, both in a `worker_threads` worker with a 15 s timeout, 512 MiB heap, 500 page and 2 M character caps, a 50 MiB uncompressed DOCX cap; text written to `<id>.txt`.
- At send: the `AttachmentStage` (a `TurnContent` stage after skill expansion) builds pi-ai content (images as `ImageContent`; text and documents as one `attachmentText(name, mime, text, path)` block, first 40,000 characters inline then "truncated, full text at <path>.txt"; a PDF with no text layer says so and gives the path), the user entry carries `{kind: "cairn.user", data: {from, attachments: [AttachmentRef]}}`, then claims are inserted (`INSERT OR IGNORE`, so a retried send is idempotent). The client fits images to 1,568 px before upload, uploads eagerly three at a time, and a send waits on the pending-work counter.
- Limits: 20 attachments, 10 MiB per image, 50 MiB per file, 40,000 inline characters per attachment, 120,000 per turn. Boot and daily sweeps remove `.tmp`, `*.part` and unclaimed uploads older than 24 hours.

### Boot and shutdown

Boot (`Boot.ts`; the HTTP listener answers static files at once and `/ws` with 503 until step 7):

1. Open `cairn.sqlite`, back it up if a migration is pending, migrate; sweep attachment temp files.
2. `BrainStore`: compare `brain.meta.json` with the installed pi-durable version and `CURRENT_SQLITE_SCHEMA_VERSION`; on a difference, `sqlite.backup` to `backups/brain-<version>-<timestamp>.sqlite` before opening.
3. Build `PiConfig` and `PiModelSource` (pi-coding-agent imported lazily here), register the bridge provider.
4. Install the extension set in its fixed order, `Harness.open`.
5. Boot repairs in order (`BootRepairs.ts`): log orphan `claude` processes with a dead parent; `ExecutorSweep` declines unfinished `apr_` ids; `retryTask()` for tasks whose approval is still pending; resume interrupted launches from `thread_launches`.
6. `harness.resume()`, start `CommitFeed`, run one `ShellProjector` reconcile from `inspect()` and the thread rows.
7. Mark ready (`/_cairn/health` reports `ready`), accept `/ws`.

Shutdown (`Shutdown.ts`, one finalizer in the root layer, `gracefulShutdownTimeout: "2 seconds"`): stop accepting upgrades and close sockets with 1001, `Claude.beginClosing()`, dispose watches and task-graph watches, `harness.close(context)` with a 5 s timeout (a `shutdown_slow` log at 20 s), close SQLite, exit. Every promise the brain holds on the Harness treats "Harness is closed" as a normal end.

## 3. Waves

### Rules every package follows

- **Ownership.** A package edits only the files and directories its block lists under "Owns". New files go inside those paths. Tests sit beside the module (`X.test.ts`).
- **Seams.** These files are edited only by the integrator at the end of a wave: `pnpm-workspace.yaml`, every `package.json`, `pnpm-lock.yaml`, `tsconfig*.json`, `oxlint.config.ts`, `vitest.config.ts`, `GLOSSARY.md`, `apps/server/src/{AppLayer,BootRepairs,ShutdownHooks}.ts`, `apps/server/src/db/Migrations.ts`, `apps/server/src/rpc/Handlers.ts`, `apps/server/src/http/Routes.ts`, `apps/server/src/brain/ExtensionSet.ts`, `apps/server/src/threads/TurnContentStages.ts`, `apps/web/src/{Model,Message,Update,View,Subscription,Route,main}.ts`, and any `import()` call site another package asks to split (D46). Each package ends its hand-off with the exact lines to add there (a layer, a handler group, a route, a migration entry, an extension, a submodel, a glossary entry).
- **Dependencies.** A package may import only what earlier waves delivered. Within a wave, packages never depend on each other. Every dependency for all of Phase 1 is declared in wave 1.0, so no package touches the lockfile; a package that truly needs a new one stops and asks the integrator.
- **Extension points instead of edits.** Where a later wave must change an earlier behaviour, the earlier package exposes a service with a default layer (`TurnContent` stages, `StopHooks`, `BootRepairs`, `ShutdownHooks`, `ExtensionSet`, `ProjectorSignals`, `ClaudeSlots`, `ClaudeAccount`, `ExtraProviders`) and the later package provides a new layer or list entry in its own file.
- **Standards.** `docs/coding-standards.md`, ADR 0004, S42 as amended by D54 (the import boundaries in section 1, "Modules"), S22 and S23 (`Option` inside, `OptionFromNullOr` at the wire, ports re-cut), S43 (one `ManagedRuntime` where pi-durable calls back into Cairn), S8 (no `Date`). Every port starts with the header: source repo, path, commit, MIT notice where the source is MIT (t3code: T3 Tools Inc.; pi: earendil-works `pi@4a080252`; pi-claude-bridge: Eli Dickinson `874fa7c2`; dot314: Eli Dickinson, Warren Winter, Nico Bailon `c157f4e6`; v1: `cairn-v1` at `1a5cd4a`), plus one line on what changed.
- **Done.** A package is done when `pnpm check` is green with its files in place and its own judges pass; judges marked "at integration" pass after the wave's merge. Real-model judges use `claude-haiku-5-5` through the bridge or an `opencode-go` model and cost cents.
- **Integration step.** After each wave the integrator applies the hand-offs, runs `pnpm check` from a clean `node_modules` when dependencies changed (duplicate vitest instances otherwise), runs the integration judges, and writes a short note in `docs/phase-1/waves.md` with the measured numbers.

| Parity (incl. transcript) | `judges/parity.ts`, `parity-structure.ts`, `behaviour.ts`, `parity-review.sh`, the user | 5C, 5D, 5E; the user at the gate |

| Daily driver | the user's full working day without herdr | after wave 5 |

## 4. What only the user can do

One script, `ops/wizards/phase-1.sh`, written with the `wizard` skill. Everything else (unit install, Caddy route, deploys, every judge on the Beelink) runs without the user.

1. **Install the PWA.** On the iPhone, open `https://code.gneiss.run` with Tailscale on, Share, Add to Home Screen, open it from the icon.
2. **Allow notifications.** In the installed app, Settings, "Notify me on this device", Allow. The wizard waits for the subscription, then runs `node judges/push.ts --send`; confirm the notification on the locked phone and that tapping it opens the thread.
3. **Cold loads.** Force-quit the PWA and open it three times; the wizard runs `tailscale ping` to the phone first, then `judges/phone-report.ts --load`, which passes only when three loads from the phone each reach the interactive mark under 1,000 ms (a run flagged `derp` is excluded and the wizard asks for another); the verdict goes to the gate page.
4. **Paste on the phone.** Screenshot the nonce page the wizard opens (`judges/paste.ts --page`), paste it into a thread in the PWA and send; `judges/phone-report.ts --paste` passes when paste-to-chip-ready plus send-to-`provider.request` is under 2,000 ms and the model's answer contains the nonce; the verdict goes to the gate page.
5. **MacBook WebKit runs**, only if the agent cannot reach the MacBook over SSH: run the printed `judges/typing.ts` and `judges/load.ts --browser webkit` commands on the MacBook.
6. **Executor re-sign-in**, only if the grant import fails or the grant was revoked: open the link the wizard prints and approve.
7. **Look at parity.** Open the gate page, compare the pairs at 1440 and 390, and say "same", or name what Cairn should do differently.
8. **The daily-driver day.** One full working day in Cairn instead of herdr, with notes on anything that made you reach for the terminal.

Three questions that block nothing and default safely: is the `sk-ant-usr` key in `auth.json` a Console API key you want offered as a metered provider (default: hidden); do you want HEIC conversion (default: no, iOS already converts); and is it acceptable that Claude threads leave their transcripts in `~/.claude/projects/<folder>/`, where your own `claude --resume` lists them and your own `claude` sweeps them after its `cleanupPeriodDays` (default: yes; a separate `CLAUDE_CONFIG_DIR` would need a second `claude` login, so it is not offered in Phase 1; a swept transcript costs one fresh session).

## 5. Risks and mitigations

| Risk | Mitigation |
| --- | --- |
| One store is one failure domain and cannot delete a thread's data | Fatal storage errors reopen through the supervisor and every client re-snapshots; whole-file backups on version change and daily; archive and delete tombstone rows; images are shrunk to 1,568 px before they enter the store; revisit if `brain.sqlite` passes a few GB |
| pi-durable's next release migrates SQLite irreversibly | `BrainStore` backs up on any version or schema change before opening; a test asserts `CURRENT_SQLITE_SCHEMA_VERSION` equals the number the code was written for; every bump rereads the changelog and spec section 12 |
| The bridge has never run end to end on pi-durable 1.4.0 | Wave 1 starts with spike 6 and the J3 runs; J2, J8, J9, J10 gate wave 3; the kill switch makes `claude-bridge` unavailable if needed |
| SDK-native resume behaves differently on Sonnet and Opus, or a killed child flushes late writes | J3 per model before relying on it; fork after any real abort; a fresh session seeded with pi's context when history diverged; Cairn never writes a Claude Code transcript |
| Anthropic policy or SDK drift | Exact pin; eligibility judge J7 on every section change and SDK bump; legal page reread at bumps; no pi preamble in prompts |
| Foldkit under a heavy streaming transcript drops keys or janks | Typing judge rerun after the real transcript lands (wave 3 integration) and on WebKit (5D); `?busy` control; React fallback (ADR 0011) stays documented |
| `virtualList` scroll anchoring misbehaves while rows grow | `judges/transcript-scroll.ts` gates 3C; D26 fallback is inside the same package |
| Chord's index-addressed ops make windowing fragile | Windowing lands only in wave 4 after the stream is proven; any unprovable rewrite sends a fresh snapshot, which is always legal; property tests compare against slicing the full view |
| Parallel packages drift from each other | One sequential contract step (1.0); dependencies only on earlier waves; seam files edited only by the integrator; extension-point services instead of cross-package edits |
| Lint cost of ports (no `any`, `!`, `typeof`, `try`, `Date.now()`, `null` re-cut to `Option`) | Ports re-cut, not pasted; 1F budgets the bridge as the largest item (it now also holds `ClaudeInstructions`, `ClaudeSlots` and `ClaudeAccount`); pilot `ClaudeGuards` and `abort` first and run `pnpm check` before porting the rest |
| Names verified only against a clone or a spike's `node_modules` | 1.0's `smoke.test.ts` imports each from the installed package; 2A reads the installed `dist` before porting |
| Fresh Claude sessions after every bridge compaction cost cache | D7's small reserve makes blocking compaction rare; J4 reports the cache numbers per divergence; if they hurt, a rebuild needs an ADR 0002 amendment with those numbers |
| Executor grant has one holder; a dev or judge brain could steal it | Only `main.ts` composes the real link (3D's grep test); `flock` lock; dev and judges use `layerFake`; the live tools judge drives the deployed brain over the protocol |
| pi-coding-agent's weight slows restarts and the 2 s convergence | Lazy import after the listener binds; `NODE_COMPILE_CACHE`; the serving gate answers static files at once; boot budget measured in `Boot.test.ts` (under 3 s to ready with 300 conversations) |
| LocalAPI whois is undocumented | Automatic fallback to `tailscale whois --json`; `judges/gate.sh` runs both and compares |
| Phone loads stall on DERP warm-up or a silent socket drop | 3 s ping, 8 s timeout, immediate reconnect on visibility; boot JSON paints the list before the socket; load reports separate DERP runs; the PWA's error page says "Open Tailscale" |
| iOS drops push subscriptions silently | Re-register at every start; delete on 404 and 410; Settings shows when the subscription is missing; every push is shown |
| Skills prompt weight (about 7,000 tokens per thread) and churn | Byte-stable render, refresh only at thread start; size shown in Settings; the user's own `settings.json` filters are the lever |
| Malicious documents | Extraction in a worker with a heap cap and timeout, `isEvalSupported: false`, DOCX central-directory size check, no output outside the attachments directory |
| Any process on the Beelink is admitted as the owner | Accepted and written into ADR 0008's consequences; such a process already runs as the user; loopback and LAN are never admitted |
| Brand leftovers from t3code's markup | Brand grep test in `pnpm check`; masked header band in parity; neutral "Cairn" text label until the branding pass |
| A wave runs long and the daily-driver day slips | Waves 1 and 2 already give a usable app on API models at `code.gneiss.run`; later waves add, so the user can start using Cairn early and report friction into wave 5 |
